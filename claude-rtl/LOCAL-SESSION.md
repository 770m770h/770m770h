# מעבר לסשן לוקלי

הפרויקט נבנה בסשן ענן ללא גישה למחשב. סשן לוקלי ב-30.8.2026 הריץ אותו לראשונה
על Windows אמיתי. מה שלמטה מתעד מה נמצא ומה תוקן.

## הקשר

- **מטרה:** תצוגת עברית מימין לשמאל ב-Claude Desktop, כולל שורות שמערבבות אנגלית.
- **מערכת:** Windows 11. המשתמש אינו מפתח — צריך הוראות קונקרטיות.
- **מצב:** הענף `claude/hebrew-rtl-display-z6f81n`, PR #3, לא מוזג. `main` ריק
  מהתוכן הזה.

## המסקנה החשובה: שתי השיטות ל-Windows חסומות בבילד הזה

**Claude Desktop 1.37937.3 מסרב לעלות כשיש דגל ניפוי בשורת הפקודה.** נמדד
ישירות, גם על עותק מבודד וגם על ההתקנה האמיתית:

```
> Claude.exe --remote-debugging-port=9223
exit code 1
Claude: refusing to start — a debugging or network-override switch is present
on the command line.
```

זה הורג את **שיטה 1** (המשגר) לגמרי — לא "הפורט לא נפתח", אלא האפליקציה מסרבת
לעלות. **שיטה 2** חסומה ממילא (`OnlyLoadAppFromAsar` דלוק + `WindowsApps`
לקריאה בלבד). כלומר בבילד הזה **אין מסלול ל-Desktop**; מה שעובד הוא
ה-userscript בדפדפן ב-claude.ai.

זו הגנה מכוונת של היצרן. עקיפה שלה (תיקון הבינארי החתום, או חיפוש דגל ניפוי
שהשומר לא תופס) היא מחוץ לגבולות הפרויקט — באותה רוח שבה כבר סורבה התקנת
תעודת-שורש עצמית בשיטה 2.

### הבאג המסוכן שנמצא בעקבות זה

המשגר, כפי שהיה כתוב, היה **סוגר את Claude ואז לא מצליח להפעיל אותו מחדש** —
ומשאיר את המשתמש בלי Claude בכלל. תוקן בשני מקומות:

1. `Test-DebugSwitchRefused` בודק את השומר **לפני** שנוגעים במשהו, ויוצא
   בהודעה ברורה בלי לסגור כלום. הבדיקה בטוחה בדיוק כי השומר קיים: התהליך
   מדפיס סירוב ומת מיד, בלי לגעת במופע הרץ.
2. אם בכל זאת הפורט לא נפתח אחרי סגירה — הסקריפט **מפעיל את Claude מחדש
   רגיל** לפני שהוא נכשל.

## מה שנמצא בסשן הלוקלי (30.8.2026)

### Claude Desktop כאן הוא גרסת Microsoft Store / MSIX

זו הנקודה שמשנה הכל. הקוד נכתב לגרסת ההתקנה הישנה (Squirrel/NSIS ב-
`%LOCALAPPDATA%\AnthropicClaude\app-x.y.z\claude.exe`). המכונה הזאת מריצה את
גרסת ה-Store:

```
C:\Program Files\WindowsApps\Claude_1.37937.3.0_x64__pzs8sxrjxfjjc\app\Claude.exe
AUMID: Claude_pzs8sxrjxfjjc!Claude
```

מכאן נגזרו הבעיות והתיקונים:

1. **המשגר לא מצא את Claude בכלל.** `Find-ClaudeExe` חיפש רק בתיקיות
   `AnthropicClaude`/`Claude` — לא ב-`WindowsApps`. **תוקן:** זיהוי דרך
   `Get-AppxPackage` נוסף וקודם בעדיפות.

2. **המשגר היה הורג את Claude Code CLI.** `Get-Process -Name claude` תופס גם
   את ה-Desktop וגם את ה-CLI (שם קובץ זהה). ריסטרט היה סוגר סשנים של CLI.
   **תוקן:** `Get-ClaudeDesktopProcess` מסנן לפי נתיב ההתקנה, אז ה-CLI אף פעם
   לא נכלל.

3. **שיטה 2 (patch-asar) חסומה כאן, סופית.** ה-fuses של הבינארי:
   `OnlyLoadAppFromAsar=enabled` ו-`EnableEmbeddedAsarIntegrityValidation=enabled`,
   ותיקיית `resources` תחת `WindowsApps` היא **לקריאה בלבד** (Access denied).
   שני חסמים בלתי-תלויים. `node windows\patch-asar.js check` מדווח על זה נכון
   עכשיו (זיהוי MSIX נוסף) ומפנה למשגר. **בגרסת Store — רק שיטה 1 רלוונטית.**

### מה שנבדק ועובד

- **56 בדיקות עוברות.**
- **ה-payload נבדק בדפדפן Chromium אמיתי** (לא רק jsdom) מול DOM שמדמה את
  Claude. כל המקרים שהמשתמש ביקש עברו: פסקה עברית → RTL; שורה שמתחילה ב-
  `Next.js` → RTL; שורה שמתחילה במספר → RTL; שורה עברית עם `code` בתוכה → RTL;
  רשימת בולטים (כולל תיקון ה-`padding-left` הפיזי → מועבר לימין); רשימה
  ממוספרת; טבלה → RTL; בלוקקוד → נשאר LTR; תיבת הכתיבה → מכולה ושורות עבריות
  RTL, שורה אנגלית לגמרי LTR. מתג הכיבוי/הדלקה מחזיר למצב המקורי נקי (25 מסומנים
  → 0 בכיבוי → 25 בהדלקה).

### איך נבדק בלי לסכן את המשתמש

**סשן ה-Claude Code הזה רץ בתוך Claude Desktop** (תהליך ה-Desktop הוא ההורה
שלו), אז סגירת Claude כדי לבדוק הייתה הורגת את הסשן באמצע. במקום זה הועתקה
תיקיית ההתקנה (609MB) ל-`%TEMP%` והבדיקה רצה על **העותק**. שם התגלה הסירוב,
ורק אחר כך אומת מול ההתקנה האמיתית (שם הוא בטוח: התהליך מת מיד, 14 תהליכי
Desktop נשארו חיים).

בלי הבדיקה המקדימה הזאת, הרצת `-Watch` הייתה סוגרת את Claude של המשתמש בלי
יכולת להחזיר אותו.

## מה שהמשתמש מריץ בפועל

```powershell
powershell -ExecutionPolicy Bypass -File windows\claude-rtl.ps1 -Diagnose
```

מדפיס את סוג ההתקנה, ואם השומר קיים — אומר זאת מפורשות ומפנה ל-userscript.
`-Watch` על בילד כזה יוצא בהודעה ברורה **בלי לגעת ב-Claude**.

**המסלול שעובד:** userscript בדפדפן ב-claude.ai (ראה README, סעיף "התקנה —
דפדפן"). `node userscript/build-userscript.js` בונה את הקובץ; נבדק שהוא תקין
ומכיל את ה-payload.

## נקודות פתוחות

- `Get-PageTargets` הורחב לקבל `page` וגם `webview`, אבל לא נצפה מול פורט חי —
  אין דרך לפתוח פורט על הבילד הזה.
- אם בעתיד יצא בילד בלי השומר, המשגר אמור לעבוד: הזיהוי, סינון התהליכים
  והרשת-ביטחון כבר מתוקנים ונבדקו.
