# claude-rtl — תמיכה בעברית מימין לשמאל ב-Claude

תצוגה תקינה של עברית וערבית ב-Claude Desktop וב-claude.ai, כולל שורות שמערבבות
אנגלית באמצע המשפט.

---

## הבעיה

Claude מציג טקסט עברי בכיוון שמאל-לימין. התוצאה: סימני פיסוק בצד הלא נכון,
רשימות הפוכות, וטבלאות שנקראות מהסוף.

## למה `dir="auto"` לבדו לא פותר את זה

הפתרון המקובל הוא לתת לדפדפן להחליט לפי כלל **"התו החזק הראשון"** של יוניקוד —
זה מה ש-`dir="auto"` עושה. הכלל הזה נשבר בדיוק במקרה שהכי נפוץ בעברית טכנית:

```
Next.js הוא פריימוורק מצוין לבניית אתרים
```

התו החזק הראשון הוא לטיני (`N`), ולכן הדפדפן קובע שהפסקה כולה LTR — הנקודה
בסוף קופצת לצד הלא נכון והשורה נקראת הפוך. אותו כשל קורה בכל שורה שמתחילה
בשם ספרייה, פקודה, או מונח באנגלית.

**מה שנעשה כאן במקום:** במקום להסתכל על התו הראשון, סופרים כמה מהתווים
ה"חזקים" בפסקה הם עבריים. פסקה שרובה עברית נשארת RTL גם אם המילה הראשונה
באנגלית. הסף ניתן לכוונון (ברירת מחדל: 30%).

```
detectDirection('Next.js הוא פריימוורק מצוין')      →  rtl   ✅
detectDirection('The quick brown fox jumps שלום')   →  ltr   ✅
```

בנוסף:

- **ספרות לא נספרות.** "יש לי 3 קבצים" הוא משפט עברי, לא מעורב.
- **קוד לא נספר.** בשורה `כדי להתקין הרץ npm install --save-dev typescript`
  המילים באנגלית הן בתוך `<code>`, ולכן הן לא מושכות את השורה ל-LTR.
- **קוד ומתמטיקה אף פעם לא מתהפכים.** בלוקי קוד, `<code>` בשורה, ו-KaTeX/MathJax
  מסומנים כ-`unicode-bidi: isolate` — הם אי עצמאי בתוך המשפט העברי, כך שגם
  הפיסוק סביבם נוחת במקום הנכון.
- **רשימות וטבלאות לפי פריט/תא.** זו הנקודה שהכי בולטת לעין: Claude מחיל כיוון
  אחד על כל ה-`<ul>` לפי התו החזק הראשון שלה — כלומר **הפריט הראשון קובע לכל
  הרשימה**. פריט ראשון שמתחיל במספר, במקף, במרכאות או במילה באנגלית מהפך את
  הרשימה כולה. כאן כל פריט נשקל בנפרד, ובנוסף גם המכולה.
  ההזחה טופלה במפורש: Claude מזיח רשימות עם `padding-left` פיזי, שלא מתהפך עם
  הכיוון — `padding-inline-start` לבדו היה מותיר ריפוד **משני הצדדים** והנקודות
  היו נתלות בקצה הלא נכון.
- **תיבת הכתיבה.** כל שורה בתיבה מקבלת כיוון משלה; תיבה ריקה מתחילה בעברית.

### עמידות לעדכונים

הקוד **לא נשען על שמות מחלקות של Claude**. הוא עובר על אלמנטים סטנדרטיים
(`p`, `li`, `td`, כותרות) ונוגע **רק באלה שמכילים תווים עבריים או ערביים בפועל**.
לכן ממשק המשתמש באנגלית — כפתורים, תפריטים, בורר המודלים — לא נוגעים בו אף פעם,
ושינוי עיצוב מצד Anthropic לא שובר את הפתרון.

## התקנה — Windows

יש שתי דרכים. **התחל מהראשונה.**

### שיטה 1: משגר (מומלץ) — לא נוגע בשום קובץ

מפעיל את Claude עם פורט הניפוי של Chromium ומזריק את הקוד דרך DevTools Protocol.
**שום קובץ בהתקנה לא משתנה**: החתימה הדיגיטלית נשארת שלמה, לא מותקנת שום תעודה,
ועדכון של Claude לא מוחק כלום.

**אין צורך ב-Node.js.** הקוד הבנוי כבר נמצא ב-`dist/`. צריך רק את PowerShell
שמגיע עם Windows.

#### הדרך הקצרה — שורה אחת

פתח PowerShell (מקש Windows, הקלד `powershell`, Enter) והדבק:

```powershell
irm https://raw.githubusercontent.com/770m770h/770m770h/refs/heads/claude/hebrew-rtl-display-z6f81n/claude-rtl/install.ps1 | iex
```

זה מוריד את מה שצריך ל-`%LOCALAPPDATA%\claude-rtl`, שם קיצור **"Claude (RTL)"**
על שולחן העבודה, ומפעיל את Claude. מכאן והלאה — לחיצה כפולה על הקיצור.

להסרה: מחק את התיקייה `%LOCALAPPDATA%\claude-rtl` ואת הקיצור. זה הכל.

#### או מתוך ההורדה הידנית

1. **Code → Download ZIP** — ודא שאתה על הברנץ' הנכון, לא על `main`.
2. היכנס לתיקייה `claude-rtl\windows`.
3. **לחיצה כפולה על `Claude-RTL.cmd`**.

זהו. Claude ייפתח עם RTL. סגירת החלון השחור עוצרת את המשגר; Claude ממשיך לרוץ.

<details>
<summary>העדפת שורת פקודה</summary>

```powershell
cd claude-rtl
powershell -ExecutionPolicy Bypass -File windows\claude-rtl.ps1 -Diagnose   # בדיקה
powershell -ExecutionPolicy Bypass -File windows\claude-rtl.ps1 -Watch      # הפעלה
powershell -ExecutionPolicy Bypass -File windows\claude-rtl.ps1 -CreateShortcut
```
</details>

אם משהו לא עובד, `Claude-RTL.cmd` מריץ אבחון אוטומטית ומשאיר את החלון פתוח.
`-Diagnose` מדפיס איפה Claude נמצא, אם הפורט נפתח, וכמה חלונות נמצאו.

> **מה המחיר:** כל עוד Claude רץ כך, הוא מאזין בפורט ניפוי על `127.0.0.1`.
> כל תוכנית שרצה תחת המשתמש שלך יכולה להתחבר אליו ולקרוא את התוכן.
> הפורט נסגר כש-Claude נסגר. אם זה מפריע לך — השתמש בשיטה 2 או ב-userscript.

### שיטה 2: תיקון קבוע — בלי משגר

```powershell
node windows\patch-asar.js check     # בדיקה מה אפשר בהתקנה שלך
node windows\patch-asar.js patch     # החלה
node windows\patch-asar.js restore   # ביטול מלא
```

`check` יגיד לך אם ההתקנה שלך מתאימה, לפני שהוא נוגע במשהו.

<details>
<summary><b>איך זה עוקף את בעיית החתימה — ולמה זה חשוב</b></summary>

הדרך המתבקשת היא לערוך את `app.asar`. בווינדוס זו מלכודת:

1. עריכת `app.asar` משנה את ה-hash שלו.
2. ה-hash הצפוי שמור בתוך `claude.exe`, אז צריך לערוך גם אותו (או לכבות את
   ה-fuse של Electron).
3. עריכת `claude.exe` **פוסלת את החתימה הדיגיטלית של Anthropic**.
4. `cowork-svc.exe` בודק את החתימה הזו ומסרב להריץ.
5. כדי לעקוף את *זה*, הפתרון הקהילתי הנפוץ **מחליף תעודה בתוך `cowork-svc.exe`
   ומתקין תעודה עצמית ל-Trusted Root של Windows**.

**הסקריפט כאן לא עושה את שלב 5, בכוונה.** התקנת שורש אמון עצמי במחשב וכיבוי
של שירות שתפקידו לאמת חתימות זו החלשה אמיתית של אבטחת המכונה — לא רק של Claude.

במקום זה הוא מנצל תכונה שקטה של Electron: האפליקציה נטענת מ-`resources/app/`
**לפני** `resources/app.asar`. כשה-fuse בשם `OnlyLoadAppFromAsar` כבוי, אפשר
לפרוס תיקייה `resources/app/` ולהשאיר את `app.asar`, את `claude.exe` ואת כל
החתימות **ללא שינוי בייט אחד**.

אם ה-fuse הזה דלוק בהתקנה שלך, `check` יגיד לך את זה ויעצור. במקרה כזה שיטה 1
היא הדרך.
</details>

> עדכון של Claude מחליף את ההתקנה ומוחק את התיקון. הרץ `patch` שוב אחריו.

## התקנה — דפדפן (claude.ai)

הדרך הכי בטוחה, אם עבודה בדפדפן מספיקה לך. אין נגיעה בקבצים, שורד עדכונים,
כיבוי בקליק.

1. התקן [Tampermonkey](https://www.tampermonkey.net/) או
   [Violentmonkey](https://violentmonkey.github.io/).
2. `node userscript/build-userscript.js`
3. פתח את `userscript/claude-rtl.user.js` וגרור אותו לחלון התוסף.

## שימוש

| פעולה | איך |
|---|---|
| **כפיית ימין-לשמאל על השורה הנוכחית** | `Ctrl+Alt+→` |
| **כפיית שמאל-לימין על השורה הנוכחית** | `Ctrl+Alt+←` |
| כיבוי/הדלקה זמניים | `Ctrl+Alt+R` |
| שחרור נעילה ידנית | `claudeRtl.unlock()` |
| "כל עברית = ימין לשמאל" | `claudeRtl.forceRtl()` |
| מה המצב כרגע | `claudeRtl.status()` |
| בדיקת החלטה על טקסט | `claudeRtl.detect('Next.js הוא פריימוורק')` |

שורה שנעלת ידנית לא תשתנה יותר לבד. ההגדרות נשמרות ב-`localStorage`.

### תיבת הכתיבה — למה היא לא קופצת

בזמן הקלדה השורה עדיין לא שלמה. אם מתחילים ב-`3 Next.js`, בכל רגע נתון אין עדיין
עברית — וכל היוריסטיקה שמחליטה מחדש בכל הקשה תהפוך את התיבה ל-LTR, ואז תהפוך
אותה חזרה כשהעברית מגיעה. הריצוד הזה הוא מה שהופך כתיבה מעורבת לבלתי אפשרית.

לכן שורה בתיבה **מחזיקה** את הכיוון שלה. היא עוברת ל-LTR רק כשהיא חד־משמעית
שורה אנגלית: אפס תווים עבריים, ולפחות 12 תווים לטיניים — כלומר לא רק תחילת
משפט. בדיקה אוטומטית מקלידה `3 Next.js הוא פריימוורק מצוין` תו אחר תו ומוודאת
**אפס** היפוכי כיוון.

### הגדרות

| שם | ברירת מחדל | משמעות |
|---|---|---|
| `threshold` | `0.3` | אחוז התווים החזקים שצריך להיות עברי כדי שהשורה תהיה RTL. `0` = כל עברית מנצחת |
| `respectAppDir` | `false` | האם לסגת מאלמנטים ש-Claude הגדיר להם `dir` בעצמו (ראה למטה) |
| `composerSticky` | `true` | השורה בתיבה מחזיקה כיוון במקום להחליט מחדש בכל הקשה |
| `composerEnglishRun` | `12` | כמה תווים לטיניים (בלי עברית) הופכים שורה ל-LTR |
| `composerMode` | `'js'` | `'js'` / `'css'` / `'off'` |
| `composerDefault` | `'rtl'` | כיוון של תיבה ריקה |
| `overrideKeys` | `'ctrl-alt'` | `'ctrl-alt'` / `'ctrl-shift'` / `false` |
| `tables` | `true` | היפוך סדר עמודות בטבלה שרובה עברית |
| `hotkey` | `true` | `Ctrl+Alt+R` |

אם תיבת הכתיבה מהבהבת או מתנהגת מוזר (ProseMirror מצייר מחדש), עבור למצב CSS:

```js
claudeRtl.config({ composerMode: 'css' })
```

## אם הכיוון עדיין תלוי במילה הראשונה

זה הסימפטום המדויק של **ההיוריסטיקה של Claude עצמו**, לא של הפתרון כאן.
Claude מחשב כיוון לפי "התו החזק הראשון" וכותב `dir="ltr"` מפורש על האלמנט.

`respectAppDir` שולט במי מנצח. ברירת המחדל היא `false` — כלומר אנחנו דורסים את
ההחלטה של Claude, כי היא בדיוק מה שבאנו לתקן. אם ההתנהגות שאתה רואה תלויה
במילה הראשונה, בדוק בקונסולה:

```js
claudeRtl.status()
// enabled: true            → הפתרון פעיל
// marked: 0                → הוא לא מגיע לתוכן בכלל (ההזרקה לא עבדה)
// dirSetByClaude: 40       → Claude מגדיר dir בעצמו על הרבה אלמנטים
// config.respectAppDir     → חייב להיות false
```

- `marked: 0` — ההזרקה לא הגיעה. הרץ `windows\claude-rtl.ps1 -Diagnose`.
- `respectAppDir: true` — הרץ `claudeRtl.config({ respectAppDir: false })`.
- עדיין נופל לצד הלא נכון בשורה מאוזנת — `claudeRtl.forceRtl()`, או
  `Ctrl+Alt+→` לכפייה על השורה הזאת בלבד.

## מגבלות ידועות

- **שורה מאוזנת באמת** (50% עברית, 50% אנגלית) תיפול לכיוון אחד. אין תשובה
  נכונה אחת כאן; כוונן את `threshold` או כפה ידנית ב-`Ctrl+Alt+→`.
- **תיבת הכתיבה** מנוהלת על ידי ProseMirror. במצב `js` ייתכן ריצוד נדיר בעריכה
  מהירה; `composerMode: 'css'` יציב יותר אבל מיישר גם שורות אנגלית לימין.
- **שיטה 1 לא שורדת סגירה** — צריך להפעיל דרך הקיצור בכל פעם.
- **שיטה 2 נמחקת בכל עדכון** של Claude.
- Claude החל לשלוח תמיכת RTL רשמית חלקית, שמבוססת על כלל התו החזק הראשון.
  כברירת מחדל אנחנו דורסים אותה (`respectAppDir: false`), כי היא הסיבה
  שהכיוון תלוי במילה הראשונה.

## הערה על תנאי השימוש

שיטה 1 לא משנה כלום בהתקנה ומשתמשת בדגל סטנדרטי של Chromium. שיטה 2 פורסת
קבצים לתיקיית ההתקנה בלי לשנות בינארי חתום. עדיין — שינוי התנהגות של אפליקציה
עלול לגעת בתנאי השימוש של Anthropic. השיקול שלך.

## פיתוח

```bash
npm install
npm test      # 56 בדיקות: לוגיקת כיוון, שכבת DOM (jsdom), והפצ'ר
npm run build
```

```
install.ps1               מתקין בשורה אחת
windows/Claude-RTL.cmd    לחיצה כפולה — שיטה 1
src/rtl-core.js       זיהוי כיוון — לוגיקה טהורה, בלי DOM
src/rtl-payload.js    שכבת DOM: סריקה, MutationObserver, מתג
src/rtl.css           כללים סטטיים (בידוד קוד, רשימות, טבלאות)
src/build.js          מאחד לקובץ IIFE אחד
windows/claude-rtl.ps1    שיטה 1 — הזרקה דרך CDP
windows/patch-asar.js     שיטה 2 — תיקון קבוע
userscript/               גרסת דפדפן
```
